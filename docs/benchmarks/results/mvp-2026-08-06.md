## 2. Partial dogfood / timed proxies (supporting remediation story)

RepoLens self-review dogfood on this repository (Phase 6.3–6.5 era), **not** a blinded study:

| Observation | Value | Why it matters |
|-------------|-------|----------------|
| Scanners-only wall time (trivy + checkov enabled) | ~27 s | Baseline CI cost without LLM |
| `--ci --fail-on HIGH` with only Medium Checkov hits | LLM **bypassed**; exit **0**; gate confidence ~80% | Triage avoids paying LLM when scanners are clean at the floor — MTTR for empty-hit PRs collapses to scanner time |
| Checkov findings seen | 3× Medium `CKV2_GHA_1` (GHA `write-all`) | Deterministic gate signal; below HIGH floor so triage does not summon LLM |
| Schema guarantee | Critical/High **require** non-empty `impact` + `codeExample` | Structural precondition for suggested-fix studies (Semgrep/CodeQL do not guarantee patch text) |

These support the **cost / path-to-fix** narrative. They do **not** substitute for remediation rate or MTTR.

## 5. Known losses / non-claims (publish early)

- RepoLens is **not** positioned as a CodeQL/Checkmarx replacement for detection depth.  
- Scanners-only may **under-detect** logic bugs that LLM/playbook passes catch — and vice versa for noisy IaC Mediums.  
- LLM variance means single-run F1 is unreliable; multi-run variance is required before any detection claim.  
- Triage CI can **miss** LLM-only issues when scanners are clean — that is an explicit cost/speed trade-off, not a silent win.
