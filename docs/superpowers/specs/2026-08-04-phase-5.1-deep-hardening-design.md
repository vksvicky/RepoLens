# Phase 5.1 — Deep coverage hardening (design)

**Status:** Design approved (Approach 1 §1 + security audit confidence)  
**Date:** 2026-08-04  
**Depends on:** Deep coverage B+C+D (rules registry, heuristics, deep passes, graceful LLM spine)  
**Next:** Phase 6 issue explain + diagrams; Phase 7 enterprise CI (renamed from former Phase 6)

## 1. Problem

PatternSorcerer deep runs surface vibes-style heuristic findings, but:

1. Coverage is dominated by **lazy N/A** (“not reviewed in this document”).  
2. **Confidence = 95%** is the model’s self-score and is easy to misread as a security or architecture grade.  
3. Mega-file heuristics noise on docs / `xcuserdata` / `pbxproj`.  
4. Low-signal items can appear as **P1 security**.  
5. Progress “still waiting” is **cumulative** across deep passes.

## 2. Goals

1. Honest checklist coverage (reject lazy N/A).  
2. **Multi-metric confidence** with a glossary — including **security audit confidence**.  
3. Quieter mega-file heuristics for non-source paths.  
4. Priority/band sanity by category.  
5. Per-pass progress timers.

## 3. Metrics model (locked)

Reports and the CLI summary expose distinct metrics. None of these is a “security score out of 100” for the product under review except where named.

| Metric | Meaning | Not |
|--------|---------|-----|
| **Gate confidence** | How sure RepoLens is that *this review package* (findings + coverage + scanners) is adequate for a commit/push-style decision | Not “% secure” or “% good architecture” |
| **Security audit confidence** | How complete/honest the **P1 / security** checklist + security findings are (sec.* coverage, scanners, P1 pass quality) | Not CVE completeness; not a grade of the app’s security posture alone |
| **Architecture audit confidence** | How complete/honest the **P3 / architecture** checklist is (arch.* coverage; full-audit only emphasizes scores) | Not a 1–10 architecture score (those remain optional `scores`) |
| **Reliability audit confidence** | Completeness of **P2** checklist (rel.*) | Optional sibling; same formula family |
| **Severity counts** | Critical / High / Medium / Low finding tallies | Independent of confidence % |
| **Coverage** | covered / valid N/A / missed checklist ids | Drives confidence penalties |
| **Scanners ran** | Tool run status | Complements security audit confidence |
| **Files scanned** | Inventory size | Context only |

### 3.1 Security audit confidence (required)

Computed after merge (not raw LLM):

```
securityAuditConfidence =
  clamp(0..100,
    base_from_p1_pass_confidence
    − penalty_missed_sec_ids
    − penalty_invalid_na_sec_ids
    + bonus_scanners_all_ran   # small, e.g. +5 capped
    − penalty_open_critical_high_security_findings  # CRITICAL −20/ea (cap 60), HIGH −10/ea (cap 50)
  )
```

- Uses `sec.*` coverage ids + P1 pass layer + scannerRuns + **open Critical/High security findings** (P1 or `sec.*` / scanner categories).  
- Lazy/invalid N/A on `sec.*` counts as missed for this metric.  
- **100% is impossible while Critical/High security findings remain.** Still not a CleanVibes posture score.  
- Document formula constants in FAQ; keep tunable under `[deep]` or `[metrics]` if needed.

### 3.2 Gate confidence (recalibrated)

```
gateConfidence =
  clamp(0..100,
    min(pass_confidences, securityAuditConfidence, architectureAuditConfidence, reliabilityAuditConfidence)
    − global_missed_penalty
    − global_invalid_na_penalty
  )
```

Never publish raw LLM 95% when missed/invalid N/A exist without applying penalties.

### 3.3 Report “Metrics” section

Markdown + JSON (`metrics` block or top-level fields) must list each metric with a one-line definition (glossary). FAQ mirrors the same table.

## 4. Lazy N/A rejection

Invalid N/A reason patterns (case-insensitive), non-exhaustive:

- “not reviewed”, “not explicitly reviewed”, “not addressed in this document”, “could be improved”, “partially addressed” without a concrete out-of-scope reason  

Valid N/A examples:

- “No HTTP/HTML surface in reviewed pack — XSS/CSRF N/A for this desktop app”  
- “No SQL/ORM usage in provided files”  

Invalid → treat as **missed** (and durability gap). Optional: one micro-prompt per pass to fill only invalid ids (5.1 MVP may skip re-prompt and just remiss).

## 5. Mega-file noise

Default **exclude** from mega-file heuristic (configurable globs):

- `**/*.md`, `**/docs/**`  
- `**/xcuserdata/**`, `**/*.xcuserstate`  
- `**/*.pbxproj`  
- common lockfiles / generated (align with inventory ignores where sensible)  

Keep source mega-files (e.g. `LocalizedString.swift`).

## 6. Priority / band sanity

- Heuristic categories (`heuristic.*`) default to P2/P3, never P1 unless explicitly security-tagged.  
- Post-process: if `priority == P1` but category is clearly non-security (style, comment prefix, docs), coerce to P2/P3.  
- LLM issues keep severity; band coercion is about **priority band**, not erasing the finding.

## 7. Progress UX

- Heartbeat timer resets at each deep pass start.  
- Label: `Deep pass k/n (p1) — LLM … (Ns this pass)`.  
- Heuristics phase has its own short phase line (no LLM wait).

## 8. Testing & acceptance

- Unit: invalid N/A → missed; mega-file skips pbxproj/docs; band coerce; confidence formulas.  
- Integration: mocked deep merge applies security + gate confidence.  
- Manual: PatternSorcerer re-run — LocalizedString/siblings/gitignore remain; confidence metrics explained; per-pass timers.

## 9. Non-goals

- UUID / explain / diagrams (Phase 6)  
- Enterprise CI (Phase 7)  
- Guaranteeing Claude-parity prose depth
