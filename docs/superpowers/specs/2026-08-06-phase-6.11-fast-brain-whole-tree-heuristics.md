# Phase 6.11 — Fast Brain: whole-tree parallel heuristics (Two-Lane product)

**Status:** Approved 2026-08-06 (Option A; AST caveat accepted)  
**Umbrella:** Extends [phase-6.x §6.3 triage routing](../../design/phase-6.x-scanner-depth-ci-gates-and-credibility.md)  
**Consumes:** Inventory honesty (cap messaging), scanners parallel runner, `--ci` triage  
**Feeds:** Phase 7 enterprise CI recipes (minutes-class PR path)

## 1. Problem

Today RepoLens conflates two jobs:

| Job | What users expect | What happens |
|-----|-------------------|--------------|
| Deterministic baseline (duplicates, mega-files, hygiene, packs) | Whole tree, seconds–minutes | Runs on **top-200 LLM inventory only** |
| LLM narrative / architecture | Sampled, expensive | Correctly capped — but heuristics were incorrectly tied to that cap |

On 5k–50k file monorepos the LLM may see &lt;1% of files. Heuristics that only see that slice make the product look like it “does not even half the job.” Raising the LLM cap (Option B) or cloud fan-out of whole packs (Option C) loses to **memory bandwidth** (local) or **$/PR** (cloud).

**Survival path:** Two-lane product — Fast Brain (whole tree, parallel, deterministic) + Slow Brain (sampled LLM on hits / scheduled deep).

## 2. Product model (System 1 / System 2)

```text
                    ┌─────────────────────────────────────┐
                    │  Lane 1 — FAST BRAIN (always)         │
 Inventory (uncapped│  • Scanners: full root (already)      │
  or high ceiling)  │  • Heuristics: full matched inventory │
                    │  • Parallel workers (I/O + hash)      │
                    │  Time target: ~30s–2 min @ 5–10k files│
                    └──────────────┬──────────────────────┘
                                   │ hits + hot_paths
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  Lane 2 — SLOW BRAIN (conditional)    │
                    │  • --ci: LLM only on scanner/heuristic│
                    │    hit files/snippets (triage)        │
                    │  • clean → LLM bypassed               │
                    │  • --deep scheduled: sample pack ≤200 │
                    │  Time: minutes in CI on hits; hours   │
                    │    only for overnight deep audits     │
                    └─────────────────────────────────────┘
```

### Explicit non-goals (traps)

- **Option B:** Raise LLM `max_files` + multithread local Ollama — does not beat ~30–80 tok/s × multi-pass packs.  
- **Option C:** Fan out full-repo packs to commercial APIs every PR — financially rejects itself (~$/PR).  
- Claiming “full-repo AI audit” when Lane 2 is sampled.

## 3. In scope (this phase)

1. **Decouple heuristics from the LLM pack**  
   - `scan_inventory` / fingerprint walk: high or separate ceiling for **matched** files used by heuristics.  
   - LLM pack selection remains capped (`max_files` default 200, triage, `--changed`).  
   - Pack heuristics (`azure-sentinel`, …) run on the **Fast Brain inventory**, not only the LLM slice.

2. **Parallelise Fast Brain heuristics**  
   - Prefer `ThreadPoolExecutor` for I/O-bound reads; `ProcessPoolExecutor` (or batched hashing) where CPU-bound content hashes are added.  
   - Sibling / path-structure checks can stay single-process over the entry list (CPU-light).  
   - Target: **~3–30 s** for duplicate/sibling/mega/hygiene style work on ~5k files on a developer laptop (order-of-magnitude; document honestly).

3. **Triage routing hookup**  
   - Merge whole-tree **heuristic** hits into the same triage inputs as scanners (severity floor, pack files).  
   - When `--ci`: LLM wakes only for hit files/snippets from scanners **and/or** heuristics (config: include heuristic hits in triage — default **on** for High+).  
   - Evidence prefix already exists for scanners; extend with heuristic hit summaries (bounded chars).

4. **Report honesty (split)**  
   - Provenance / Metrics:  
     - `fastBrainFiles` = matched inventory count used for heuristics  
     - `llmPackFiles` = files sent to the model (0 if bypassed)  
   - Progress: `Fast brain: N files, H heuristic finding(s) (parallel)` then existing LLM/triage lines.  
   - Durability gap if LLM pack truncated while Fast Brain saw more.

5. **Docs**  
   - FAQ + command-atlas: Fast vs Slow brain; org guidance already started under inventory cap.  
   - Update phase-6.x umbrella + phases.md checkbox for 6.11.

## 4. Out of scope

- Raising default LLM pack to thousands  
- Multi-GPU / multi-process Ollama fan-out  
- Cloud parallel full-repo LLM  
- New duplicate-detection algorithms beyond improving **scope + parallelism** of existing heuristics (content-hash duplicates may be a **stretch** in the same phase if cheap)  
- Phase 7 Jenkins/email packaging (consumes this; separate)

## 5. Technical sketch

### 5.1 Inventory

| Consumer | Source | Cap |
|----------|--------|-----|
| Fast Brain heuristics + pack heuristics | `scan_inventory(..., max_files=fast_max)` | Default **high** (e.g. 10_000) or `0` = uncapped matched |
| Adaptive fingerprints | Prefer Fast Brain set (so “dropped from pack” ≠ heuristic blindness) | Same as Fast Brain |
| LLM / deep pack | Existing adaptive + triage selection | Default **200** |

Config sketch:

```toml
[general]
# LLM / deep sample (unchanged default)
max_files = 200

[fast_brain]
# Whole-tree deterministic lane
max_files = 10000          # 0 = no cap beyond ignores/size
parallel_workers = 8       # heuristic I/O pool
triage_include_heuristics = true
```

### 5.2 Pipeline order (review)

```text
1. Inventory fast (high cap) + inventory llm slice (≤200) — or one walk, two views
2. Scanners(full root) ∥ Fast heuristics(fast inventory)   # parallel lanes
3. Merge issues; triage plan from scanner + heuristic hits
4. Slow brain: bypass | snippet/hit pack LLM | scheduled deep sample
5. Report: provenance split + durability notes
```

### 5.3 Heuristics runner

- `run_heuristics(root, fast_entries, *, workers=…)`  
- Per-entry readers (mega-file line counts, script hygiene, todo density, pack scans): map over chunks with a thread pool.  
- Global reducers (siblings, gitignore/ci gaps): after map, or dedicated passes on full entry list.  
- Preserve `source=heuristic` and stable categories.

**Fast Brain heuristic budget (AST caveat):** Fast Brain work must stay in the **seconds–low minutes** band on multi-thousand-file trees. Prefer **regex, line-scanning, filesystem stats, and hashing**. Do **not** put deep **AST** traversal (e.g. Python `ast` call-graph / full parse of every file) or equivalent JS/TS AST walks in the Fast Brain — even with `ProcessPoolExecutor`, 5k–10k full parses will blow the ~30s–2 min target. Heavy structural analysis belongs in:

1. **Slow Brain** (LLM on triage hits / scheduled deep sample), or  
2. A **deterministic scanner** built for that job (Semgrep, etc. — OCaml/Rust-speed tools already on Lane 1 scanners).

### 5.4 Triage

Extend `triage_llm_plan` (or wrapper) so heuristic issues at/above `severity_floor` contribute triage hits and pack files, with the same `max_triage_files` / snippet caps as scanners. Fail-on in `--ci` remains **scanner-preferring** unless config explicitly widens (do **not** let Low heuristic noise fail the build by default).

## 6. Exit criteria

- [ ] On a fixture tree with &gt;200 files, sibling/mega (or pack) heuristics find issues **outside** the LLM top-200.  
- [ ] Progress/report show Fast Brain file count ≠ LLM pack count when truncated.  
- [ ] `--ci` with only heuristic High hit can route LLM to that file (when `triage_include_heuristics`); clean scanners+heuristics → LLM bypass.  
- [ ] Parallel heuristics do not crash under worker&gt;1; tests cover map/reduce determinism (sorted outputs).  
- [ ] FAQ/command-atlas describe Two-Lane; Option B/C rejected with rationale.  
- [ ] Dogfood: RepoLens repo Fast Brain finishes in **well under** deep LLM time (seconds–low minutes).

## 7. Risks

| Risk | Mitigation |
|------|------------|
| Fast inventory of 50k files OOMs | Cap `fast_brain.max_files`; stream/chunk; ignore rules |
| Heuristic noise fails CI | `--ci` fail-on stays scanner-primary; heuristic triage opt-in severity floor |
| Fingerprint DB churn | Sync fingerprints to Fast Brain set, not LLM slice |
| Users still expect hour-long deep = whole tree | Report chrome + FAQ; never imply Lane 2 is full coverage |
| AST-heavy heuristics in Fast Brain | Forbidden by §5.3 budget: regex/line/stat/hash only; AST → Slow Brain or Semgrep-class scanner |

## 8. Implementation slices (for plan)

1. Config + dual inventory views + report/progress provenance  
2. Heuristics parallel runner + tests on &gt;200 fixture  
3. Triage includes heuristic hits  
4. Docs / phases / CHANGELOG / command-atlas  

## 9. Decision record

**Approved direction:** Option A (Two-Lane). Reject B (local LLM brute force) and C (cloud full-pack fan-out) for PR-default product shape.
