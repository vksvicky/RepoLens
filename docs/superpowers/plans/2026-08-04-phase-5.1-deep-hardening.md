# Phase 5.1 Deep Coverage Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make deep-coverage reports honest and readable: reject lazy N/A, expose gate + **security audit confidence** (and arch/rel siblings) with a glossary, quiet mega-file noise, fix priority banding, and reset LLM wait timers per deep pass.

**Architecture:** Post-merge scoring in a new `metrics.py` module; coverage validation extends `coverage.py`; mega-file skips use configurable globs; band coercion is a pure function over issues; pipeline moves `prog.waiting` inside each deep pass. Report/CLI/FAQ surface the glossary.

**Tech Stack:** Python 3.11+, existing `pipeline`/`coverage`/`heuristics`/`schema`/`report`/`progress`, pytest, Typer/Rich.

### Task 2: Audit metrics + gate confidence

**Files:** `src/repolens/metrics.py`, `src/repolens/schema.py`, `tests/test_metrics.py`

**Interfaces:**
```python
@dataclass
class AuditMetrics:
    gate_confidence: int
    security_audit_confidence: int
    architecture_audit_confidence: int
    reliability_audit_confidence: int

def compute_band_confidence(
    *,
    prefix: str,  # "sec." | "arch." | "rel."
    base_confidence: int,
    coverage: CoverageResult,
    scanner_bonus: int = 0,
) -> int: ...

def compute_audit_metrics(
    *,
    pass_confidences: dict[str, int],  # p1/p2/p3
    coverage: CoverageResult,
    scanner_runs: list[ScannerRun],
) -> AuditMetrics: ...
```

**Formula (initial constants — document in module docstring + FAQ):**
- Per missed id in band: −4 (cap −40)
- Per invalid/lazy N/A remapped: −3 (cap −30)
- Scanners all `ran`: +5 on security only (cap 100)
- `gate_confidence = min(band confidences present, min pass confidences) − global missed/lazy penalties`

- [ ] **Step 1:** Failing tests for security audit confidence drop when `sec.*` missed; gate ≤ security when security is lowest.

- [ ] **Step 2:** Add schema fields (backward compatible defaults); wire `FindingReport.confidence = metrics.gate_confidence`.

- [ ] **Step 3:** Commit when user asks.

### Task 4: Priority / band sanity

**Files:** new `src/repolens/bands.py`, call from pipeline after merge

**Rules (MVP):**
- `category.startswith("heuristic.")` → priority at most P2 (if was P1 → P2)
- Non-security categories (e.g. contains `practice_review` with title matching comment/style, or category allowlist) → demote P1→P2 when clearly not sec.*

Keep MVP tight: **always** demote `heuristic.*` off P1; demote issues whose category is not `sec.*` / `security` / scanner security and priority is P1 **only if** category is in a denylist (`sec.practice_review` alone is too broad — prefer: if priority P1 and category not starting with `sec.` and not scanner tool categories → P2).

Simpler locked MVP:
1. All `heuristic.*` → max P2  
2. If `priority == P1` and not (`category.startswith("sec.")` or category in scanner security set) → coerce to P2  

- [ ] **Step 1:** Failing test: PHP-style finding with P1 + `sec.practice_review` — follow product choice: either leave (security practice) OR add title heuristics. **Locked for plan:** coerce only when category lacks `sec.`/`security`/`gitleaks`/`semgrep`/`osv` OR category is `heuristic.*`. Document that true `sec.practice_review` P1 stays; mega-file never P1.

- [ ] **Step 2:** Implement `coerce_issue_bands(issues) -> list[Issue]`.
